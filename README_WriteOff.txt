==============================================================================
 МОДУЛЬ "АКТ О СПИСАНИИ СИЗ" (SizCardApi)
==============================================================================

Расширение проекта SizCardApi (электронная карточка учёта СИЗ).
Модуль автоматически находит просроченные и непригодные СИЗ, формирует акт
списания и выводит списанные изделия из резерва (статус "Списано").

Основной README проекта описывает карточки учёта СИЗ. Этот файл описывает
только модуль актов списания.


------------------------------------------------------------------------------
 1. ЧТО УМЕЕТ МОДУЛЬ
------------------------------------------------------------------------------

 - Показывает список СИЗ, подлежащих списанию, с причиной.
 - Формирует акт списания по выбранным изделиям (или по всем сразу).
 - Присваивает акту номер вида АКТ-2026-0001.
 - Переводит включённые в акт карточки в статус "Списано".
 - Хранит акты и позволяет открыть любой акт позже.
 - Выводит печатную форму акта (печать из браузера).


------------------------------------------------------------------------------
 2. ПРАВИЛА СПИСАНИЯ
------------------------------------------------------------------------------

СИЗ подлежит списанию, если одновременно:

 1) его статус не "Списано", и
 2) выполняется хотя бы одно из условий:
      - срок годности (ExpiryDate) уже истёк, то есть раньше сегодняшней даты;
      - заключение о годности (Conclusion) равно "Не годен".

Причина списания в акте:
 - Expired - "Истёк срок годности" (приоритет, если истёк срок);
 - Unfit   - "Признано негодным" (заключение "Не годен").

Важно:
 - Отметка "срок годности истекает в ближайшие 6 месяцев" (IsExpiringSoon)
   к списанию не относится: это только предупреждение, изделие ещё годно.
 - Списываются карточки в любом статусе, кроме "Списано" (на хранении,
   выдано на руки, на проверке). У выданных изделий владелец сохраняется
   в строке акта.
 - Заключение сравнивается как точная строка "Не годен". В форме карточки
   это значение выбирается из списка.


------------------------------------------------------------------------------
 3. ЧТО ПРОИСХОДИТ ПРИ СОЗДАНИИ АКТА
------------------------------------------------------------------------------

 1) Выбираются карточки, подлежащие списанию (все или только указанные).
 2) Если списывать нечего, либо среди выбранных есть неподходящие
    (уже списаны, срок не истёк), акт не создаётся, возвращается ошибка 400.
 3) Формируется номер: АКТ-<год акта>-<порядковый номер в году>, например
    АКТ-2026-0001. Номер уникален (уникальный индекс в базе).
 4) Для каждого изделия создаётся строка акта. В неё копируются данные
    изделия на момент списания: наименование, инвентарный номер, партия,
    заводской номер, размер, место хранения, срок годности, владелец.
 5) Карточки получают статус "Списано" и заключение "Не годен".
 6) Акт и смена статусов сохраняются одним вызовом SaveChanges, то есть
    одной транзакцией: либо создано всё, либо ничего.

Строки акта хранят копию данных. Если карточку позже изменят или удалят,
акт останется прежним. Связь строки с карточкой (SizCardId) - обычное число,
а не внешний ключ, поэтому акт не мешает удалению карточки.


------------------------------------------------------------------------------
 4. ЗАПУСК
------------------------------------------------------------------------------

Требуется .NET 8 SDK.

Запускать через файл решения SizCardApi.sln в Visual Studio, профиль
"SizCardApi" (зелёная кнопка запуска). Тогда применяются настройки из
Properties/launchSettings.json:

   http://localhost:57488      (также https://localhost:57487)

Подождать, пока в консоли появится строка "Now listening on", затем открыть:

   http://localhost:57488/index.html      - карточки СИЗ
   http://localhost:57488/writeoff.html   - акты списания
   http://localhost:57488/swagger         - документация API

Запуск SizCardApi.exe напрямую из папки bin не рекомендуется: сервер стартует
на другом порту с другими параметрами.

База данных: SQLite, файл sizcards.db в папке проекта. Создаётся
автоматически.


------------------------------------------------------------------------------
 5. РАБОТА СО СТРАНИЦЕЙ АКТОВ (writeoff.html)
------------------------------------------------------------------------------

 1) В таблице "Подлежат списанию" отметьте нужные изделия (по умолчанию
    отмечены все).
 2) Укажите дату акта, председателя и членов комиссии, примечание
    (необязательно).
 3) Нажмите "Сформировать акт списания" и подтвердите действие.
 4) Откроется печатная форма акта. Кнопка "Печать" отправляет её на печать
    браузера (лишние элементы страницы скрываются).
 5) Все созданные акты перечислены в таблице "Созданные акты"; кнопка
    "Открыть / печать" показывает любой из них.

Чтобы проверить модуль на тестовых данных: в index.html поставьте любой
карточке срок годности в прошлом (или заключение "Не годен"), затем обновите
страницу актов.


------------------------------------------------------------------------------
 6. API
------------------------------------------------------------------------------

Базовый адрес: /api/writeoff
Даты в формате ГГГГ-ММ-ДД, перечисления передаются строками.

GET /api/writeoff/candidates
    Список СИЗ, подлежащих списанию.
    Ответ 200: массив объектов
      { id, name, inventoryNumber, batchNumber, expiryDate,
        storageLocation, owner, status, reason }
      reason: "Expired" | "Unfit"

POST /api/writeoff/acts
    Создать акт.
    Тело запроса:
      {
        "actDate": "2026-10-05",            // необязательно, по умолчанию сегодня
        "chairmanName": "Иванов И.И.",      // необязательно
        "commissionMembers": "Петров П.П., Сидоров С.С.",   // необязательно
        "note": "",                         // необязательно
        "cardIds": [1, 2]                   // необязательно: пусто = все
      }
    Ответ 201: созданный акт со строками (items).
    Ответ 400: { "error": "текст причины" } - нечего списывать или выбраны
               неподходящие карточки.

GET /api/writeoff/acts
    Список актов, новые сверху, со строками.

GET /api/writeoff/acts/{id}
    Один акт со строками. Ответ 404, если акта нет.

Пример создания акта по всем подлежащим изделиям (curl):

    curl -X POST http://localhost:57488/api/writeoff/acts ^
         -H "Content-Type: application/json" ^
         -d "{\"chairmanName\":\"Иванов И.И.\"}"

 7. СТРУКТУРА (файлы модуля)
------------------------------------------------------------------------------

Models/
  WriteOffAct.cs          акт списания
  WriteOffActItem.cs      строка акта (снимок данных изделия)
  WriteOffReason.cs       причина списания (enum) и константы заключений
DTOs/
  WriteOffDtos.cs         CreateWriteOffActDto, WriteOffCandidateDto
Repositories/
  IWriteOffRepository.cs
  WriteOffRepository.cs   выборка кандидатов, нумерация, чтение/запись актов
Services/
  IWriteOffService.cs
  WriteOffService.cs      вся логика создания акта
Controllers/
  WriteOffController.cs   REST-методы
Data/
  AppDbContext.cs         DbSet-ы актов, уникальный индекс номера акта
  DbInitializer.cs        создание таблиц актов в уже существующей базе
wwwroot/
  writeoff.html           страница актов и печатная форма
  index.html              добавлены ссылка на акты и поле "Заключение"
Program.cs                регистрация репозитория и сервиса, DbInitializer

Архитектура та же, что у карточек: Controller -> Service -> Repository
(через интерфейсы) -> AppDbContext (EF Core, SQLite).


------------------------------------------------------------------------------
 8. ТАБЛИЦЫ БАЗЫ ДАННЫХ
------------------------------------------------------------------------------

WriteOffActs
  Id, ActNumber (уникален), ActDate, CreatedAt,
  ChairmanName, CommissionMembers, Note

WriteOffActItems
  Id, WriteOffActId (внешний ключ, каскадное удаление), SizCardId, Reason,
  Name, InventoryNumber, BatchNumber, SerialNumber, Size,
  StorageLocation, ExpiryDate, Owner

Особенность: метод EnsureCreated() создаёт таблицы только в пустой базе.
Если sizcards.db уже существовал, новые таблицы в нём не появились бы,
поэтому DbInitializer при каждом старте выполняет CREATE TABLE IF NOT EXISTS.
Существующие таблицы он не затрагивает, на новой базе ничего не меняет.


------------------------------------------------------------------------------
 9. ОГРАНИЧЕНИЯ И ИЗВЕСТНЫЕ НЮАНСЫ
------------------------------------------------------------------------------

 - Списание выполняется вручную кнопкой. Фонового автоматического списания
   без подтверждения комиссии нет.
 - Акт нельзя изменить или удалить через API (методов нет).
 - Порядковый номер акта считается как количество актов за год акта плюс
   один. Если при одновременном создании двух актов номера совпадут,
   уникальный индекс не даст сохранить второй, нужно повторить запрос.
 - Форма карточки в index.html не передаёт часть полей (дата поступления,
   дата последней проверки, звено НФГО), поэтому при редактировании через
   форму эти поля обнуляются.
 - Автоматических тестов для модуля нет.
